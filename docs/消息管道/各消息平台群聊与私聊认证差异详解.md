# 各消息平台群聊与私聊认证差异详解

## 1. 概述

不同消息平台在群聊和私聊的认证机制上有显著差异。本文档通过具体场景举例，详细说明各平台的认证差异。

---

## 2. 飞书 (Feishu/Lark)

### 2.1 认证机制

| 场景     | 认证方式                                      | 配置项                      |
| -------- | --------------------------------------------- | --------------------------- |
| **私聊** | dmPolicy + allowFrom + pairing                | 用户级白名单                |
| **群聊** | groupPolicy + groupAllowFrom + requireMention | 群组级白名单 + 用户级白名单 |

### 2.2 场景举例

#### 场景 A：私聊 - 配对模式

```
配置：
{
  channels: {
    feishu: {
      dmPolicy: "pairing",
      allowFrom: [],
    },
  },
}

用户张三 (ou_zhangsan) 第一次私聊 Bot：
┌─────────────────────────────────────────────────────────────────────────────┐
│  张三: 你好                                                                  │
│                                                                             │
│  Bot: 欢迎使用 OpenClaw！                                                   │
│       您的配对码是: XYZ12345                                                │
│       请将此配对码发送给管理员进行批准。                                     │
│       配对码 1 小时内有效。                                                 │
└─────────────────────────────────────────────────────────────────────────────┘

管理员批准：
$ openclaw pairing list feishu
CODE        SENDER              CREATED
XYZ12345    ou_zhangsan         10:30:00

$ openclaw pairing approve feishu XYZ12345
Approved pairing request from ou_zhangsan

张三再次发送消息：
┌─────────────────────────────────────────────────────────────────────────────┐
│  张三: 你好                                                                  │
│                                                                             │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 场景 B：群聊 - 两层白名单

```
配置：
{
  channels: {
    feishu: {
      groupPolicy: "allowlist",
      groupAllowFrom: ["oc_tech_team", "oc_sales_team"],  // 只允许这两个群
      allowFrom: ["ou_zhangsan", "ou_lisi"],              // 只允许这两个用户
      requireMention: true,
    },
  },
}

场景 B1：群组不在白名单
┌─────────────────────────────────────────────────────────────────────────────┐
│  群组: oc_random_group (不在白名单)                                         │
│                                                                             │
│  张三: @Bot 你好                                                            │
│  Bot: (无响应)                                                              │
│                                                                             │
│  日志: feishu: group oc_random_group not in groupAllowFrom                 │
└─────────────────────────────────────────────────────────────────────────────┘

场景 B2：群组在白名单，但用户不在
┌─────────────────────────────────────────────────────────────────────────────┐
│  群组: oc_tech_team (在白名单)                                              │
│                                                                             │
│  王五 (不在 allowFrom): @Bot 你好                                           │
│  Bot: (无响应)                                                              │
│                                                                             │
│  日志: feishu: sender ou_wangwu not in group sender allowlist              │
└─────────────────────────────────────────────────────────────────────────────┘

场景 B3：群组和用户都在白名单，但未 @Bot
┌─────────────────────────────────────────────────────────────────────────────┐
│  群组: oc_tech_team (在白名单)                                              │
│                                                                             │
│  张三 (在 allowFrom): 大家好                                                │
│  Bot: (无响应，但记录到历史)                                                │
│                                                                             │
│  张三: @Bot 帮我查一下天气                                                  │
│  Bot: 今天天气晴朗，气温 28°C...                                           │
└─────────────────────────────────────────────────────────────────────────────┘

场景 B4：全部通过
┌─────────────────────────────────────────────────────────────────────────────┐
│  群组: oc_tech_team (在白名单)                                              │
│                                                                             │
│  张三 (在 allowFrom): @Bot 你好                                             │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3. Telegram

### 3.1 认证机制

| 场景     | 认证方式                    | 特殊机制              |
| -------- | --------------------------- | --------------------- |
| **私聊** | 所有私聊消息都会被 Bot 接收 | 无需特殊认证          |
| **群聊** | Privacy Mode + Bot 权限     | 需关闭隐私模式或 @Bot |

### 3.2 Privacy Mode 详解

```
Telegram Bot 默认开启隐私模式 (Privacy Mode)：

开启时 (默认)：
┌─────────────────────────────────────────────────────────────────────────────┐
│  私聊：                                                                      │
│  ✅ 接收所有私聊消息                                                        │
│                                                                             │
│  群聊：                                                                      │
│  ✅ 接收 @Bot 的消息                                                        │
│  ✅ 接收以 / 开头的命令                                                     │
│  ✅ 接收 Bot 消息的回复                                                     │
│  ❌ 不接收普通群聊消息                                                      │
│  ❌ 不接收其他用户之间的对话                                                │
└─────────────────────────────────────────────────────────────────────────────┘

关闭时：
┌─────────────────────────────────────────────────────────────────────────────┐
│  私聊：                                                                      │
│  ✅ 接收所有私聊消息                                                        │
│                                                                             │
│  群聊：                                                                      │
│  ✅ 接收群内所有消息                                                        │
│  ⚠️ 需要 Bot 是群管理员                                                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 场景举例

#### 场景 A：私聊 - 无需认证

```
配置：
{
  channels: {
    telegram: {
      botToken: "123456:ABC...",
      // 无需额外配置，所有私聊都被接收
    },
  },
}

用户 @user1 私聊 Bot：
┌─────────────────────────────────────────────────────────────────────────────┐
│  @user1: 你好                                                               │
│                                                                             │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘

说明：Telegram Bot 自动接收所有私聊消息，无需任何认证配置。
```

#### 场景 B：群聊 - 隐私模式开启（默认）

```
Bot 设置：Privacy Mode = ON (默认)

群组：Tech Team
┌─────────────────────────────────────────────────────────────────────────────┐
│  用户 A: 大家好                                                             │
│  Bot: (不接收，隐私模式)                                                    │
│                                                                             │
│  用户 B: 今天天气怎么样                                                     │
│  Bot: (不接收，隐私模式)                                                    │
│                                                                             │
│  用户 A: @MyBot 你好                                                        │
│  Bot: 你好！有什么可以帮助你的？                                            │
│                                                                             │
│  用户 B: /weather                                                           │
│  Bot: 今天天气晴朗，气温 28°C...                                           │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 场景 C：群聊 - 隐私模式关闭

```
Bot 设置：Privacy Mode = OFF (通过 @BotFather 设置)
要求：Bot 必须是群管理员

群组：Tech Team
┌─────────────────────────────────────────────────────────────────────────────┐
│  用户 A: 大家好                                                             │
│  Bot: (接收消息)                                                            │
│  用户 A: 今天天气怎么样                                                     │
│  Bot: (接收消息)                                                            │
│                                                                             │
│  OpenClaw 配置：                                                            │
│  {                                                                          │
│    groupPolicy: "allowlist",                                                │
│    groupAllowFrom: [-1001234567890],  // 群组 ID                            │
│    requireMention: true,  // OpenClaw 层面仍可配置是否需要 @               │
│  }                                                                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 4. Discord

### 4.1 认证机制

| 场景     | 认证方式              | 特殊机制         |
| -------- | --------------------- | ---------------- |
| **私聊** | Bot 需要私信权限      | 用户可能关闭私信 |
| **群聊** | 服务器权限 + 频道权限 | 角色权限系统     |

### 4.2 权限系统

```
Discord 使用多层级权限系统：

┌─────────────────────────────────────────────────────────────────────────────┐
│  权限层级                                                                    │
│                                                                             │
│  1. Bot 应用权限 (Bot Permissions)                                          │
│     - Send Messages: 发送消息                                               │
│     - Read Message History: 读取历史                                        │
│     - Mention Everyone: @everyone 权限                                      │
│                                                                             │
│  2. Gateway Intents (意图)                                                  │
│     - MESSAGE_CONTENT: 读取消息内容                                         │
│     - GUILD_MESSAGES: 接收服务器消息                                        │
│     - DIRECT_MESSAGES: 接收私信                                             │
│                                                                             │
│  3. 服务器角色权限                                                           │
│     - 管理员可以配置 Bot 在特定频道的权限                                   │
│     - 可以限制 Bot 只在特定频道工作                                        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 场景举例

#### 场景 A：私聊 - 需要用户开启私信

```
配置：
{
  channels: {
    discord: {
      token: "Bot xxx...",
      intents: ["DIRECT_MESSAGES"],
    },
  },
}

用户 @user1 私聊 Bot：
┌─────────────────────────────────────────────────────────────────────────────┐
│  情况 1：用户允许服务器成员私信                                              │
│                                                                             │
│  @user1: 你好                                                               │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  情况 2：用户关闭了私信                                                      │
│                                                                             │
│  @user1: (无法发送私信给 Bot)                                               │
│  错误: Cannot send messages to this user                                    │
│                                                                             │
│  解决方案：用户需要在服务器设置中开启"允许服务器成员私信"                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 场景 B：群聊 - 频道权限控制

```
配置：
{
  channels: {
    discord: {
      token: "Bot xxx...",
      intents: ["GUILD_MESSAGES", "MESSAGE_CONTENT"],
      // OpenClaw 层面的配置
      groupPolicy: "allowlist",
      groupAllowFrom: ["123456789"],  // 频道 ID
      requireMention: true,
    },
  },
}

服务器：My Server
频道：#general (ID: 123456788, 不在白名单)
频道：#bot-chat (ID: 123456789, 在白名单)

┌─────────────────────────────────────────────────────────────────────────────┐
│  #general 频道 (不在白名单)                                                 │
│                                                                             │
│  用户 A: @MyBot 你好                                                        │
│  Bot: (OpenClaw 拒绝处理，频道不在白名单)                                   │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  #bot-chat 频道 (在白名单)                                                  │
│                                                                             │
│  用户 A: 大家好                                                             │
│  Bot: (不响应，requireMention = true)                                       │
│                                                                             │
│  用户 A: @MyBot 你好                                                        │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 5. Slack

### 5.1 认证机制

| 场景     | 认证方式            | 特殊机制            |
| -------- | ------------------- | ------------------- |
| **私聊** | App Home DM         | 需要用户主动发起    |
| **群聊** | 频道权限 + App 订阅 | Event Subscriptions |

### 5.2 App Home 与私信

```
Slack 的私信机制比较特殊：

┌─────────────────────────────────────────────────────────────────────────────┐
│  App Home                                                                    │
│                                                                             │
│  用户需要：                                                                  │
│  1. 在 Slack 中点击 App                                                     │
│  2. 进入 App 的 "Home" 标签页                                               │
│  3. 点击 "Message" 标签发起私信                                             │
│                                                                             │
│  或者：                                                                      │
│  1. 在任何频道 @mention App                                                 │
│  2. App 可以通过 DM 回复                                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.3 场景举例

#### 场景 A：私聊 - App Home DM

```
配置：
{
  channels: {
    slack: {
      mode: "socket",
      appToken: "xapp-...",
      botToken: "xoxb-...",
      // 启用 App Home DM
    },
  },
}

用户通过 App Home 发起私信：
┌─────────────────────────────────────────────────────────────────────────────┐
│  App: OpenClaw                                                              │
│  标签: Messages                                                             │
│                                                                             │
│  用户: 你好                                                                  │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘

说明：Slack 不需要额外的用户认证，只要用户能访问 App 就可以私信。
```

#### 场景 B：群聊 - 频道订阅

```
配置：
{
  channels: {
    slack: {
      mode: "socket",
      appToken: "xapp-...",
      botToken: "xoxb-...",
      // OpenClaw 层面配置
      groupPolicy: "allowlist",
      groupAllowFrom: ["C1234567890"],  // 频道 ID
    },
  },
}

需要订阅的事件：
- app_mention: Bot 被提及
- message.channels: 频道消息

频道：#general (C1234567890, 在白名单)
频道：#random (C1234567891, 不在白名单)

┌─────────────────────────────────────────────────────────────────────────────┐
│  #random 频道 (不在白名单)                                                  │
│                                                                             │
│  用户 A: @OpenClaw 你好                                                     │
│  Bot: (OpenClaw 拒绝处理)                                                   │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  #general 频道 (在白名单)                                                   │
│                                                                             │
│  用户 A: @OpenClaw 你好                                                     │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘

注意：Slack Bot 默认只在被 @mention 时收到通知（类似 Privacy Mode）。
```

## 6. WhatsApp

### 6.1 认证机制

| 场景     | 认证方式     | 特殊机制       |
| -------- | ------------ | -------------- |
| **私聊** | 账号收到消息 | 无需认证       |
| **群聊** | 账号在群内   | 需要被邀请加入 |

### 6.2 特点

```
WhatsApp 使用个人账号模式，不是 Bot API：

┌─────────────────────────────────────────────────────────────────────────────┐
│  OpenClaw 在 WhatsApp 中的角色                                              │
│                                                                             │
│  OpenClaw = 一个普通的 WhatsApp 用户                                        │
│                                                                             │
│  私聊：                                                                      │
│  - 任何用户都可以给 OpenClaw 账号发消息                                     │
│  - 相当于给一个朋友发消息                                                   │
│  - 无法在平台层面限制                                                       │
│                                                                             │
│  群聊：                                                                      │
│  - OpenClaw 账号必须被邀请加入群组                                          │
│  - 加入后可以接收群内所有消息                                               │
│  - 相当于一个普通群成员                                                     │
│                                                                             │
│  认证控制：                                                                  │
│  - 平台层面：无限制                                                         │
│  - OpenClaw 层面：可以配置 dmPolicy 和 groupPolicy                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.3 场景举例

#### 场景 A：私聊 - 账号级接收

```
配置：
{
  channels: {
    whatsapp: {
      enabled: true,
      authDir: "~/.openclaw/whatsapp-auth",
      // OpenClaw 层面的认证
      dmPolicy: "pairing",  // 需要配对
    },
  },
}

用户 +1234567890 发送私聊：
┌─────────────────────────────────────────────────────────────────────────────┐
│  WhatsApp 平台层面：                                                         │
│  - 消息被推送给 OpenClaw 账号（因为账号就是接收者）                         │
│                                                                             │
│  OpenClaw 认证层面：                                                         │
│  - dmPolicy = "pairing"                                                     │
│  - 用户 +1234567890 未配对                                                  │
│  - 发送配对码                                                               │
│                                                                             │
│  用户: 你好                                                                  │
│  Bot: 欢迎使用 OpenClaw！                                                   │
│       您的配对码是: WA123456                                                │
│       请将此配对码发送给管理员进行批准。                                     │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 场景 B：群聊 - 必须被邀请

```
配置：
{
  channels: {
    whatsapp: {
      enabled: true,
      groupPolicy: "allowlist",
      groupAllowFrom: ["120363xxx@g.us"],  // 群组 ID
    },
  },
}

场景 B1：OpenClaw 账号不在群内
┌─────────────────────────────────────────────────────────────────────────────┐
│  WhatsApp 平台层面：                                                         │
│  - OpenClaw 账号不在群内                                                    │
│  - 消息不会被推送给 OpenClaw                                                │
│  - OpenClaw 完全不知道这个群的消息                                          │
│                                                                             │
│  用户 A 在群内: @OpenClaw 你好                                              │
│  Bot: (不响应，因为账号根本不在群里)                                        │
│                                                                             │
│  解决：邀请 OpenClaw 账号加入群组                                           │
└─────────────────────────────────────────────────────────────────────────────┘

场景 B2：OpenClaw 账号在群内，但群不在白名单
┌─────────────────────────────────────────────────────────────────────────────┐
│  WhatsApp 平台层面：                                                         │
│  - OpenClaw 账号在群内                                                      │
│  - 消息被推送给 OpenClaw                                                    │
│                                                                             │
│  OpenClaw 认证层面：                                                         │
│  - 群组 ID "120363yyy@g.us" 不在 groupAllowFrom                            │
│  - 拒绝处理                                                                 │
│                                                                             │
│  用户 A 在群内: 你好                                                         │
│  Bot: (不响应，群组未授权)                                                  │
└─────────────────────────────────────────────────────────────────────────────┘

场景 B3：全部通过
┌─────────────────────────────────────────────────────────────────────────────┐
│  群组: 120363xxx@g.us (在白名单)                                            │
│  OpenClaw 账号在群内                                                         │
│                                                                             │
│  用户 A: 你好                                                                │
│  Bot: 你好！有什么可以帮助你的？                                            │
│                                                                             │
│  注意：WhatsApp 没有 @mention 机制，所有消息都会被处理                      │
│        （除非 OpenClaw 层面配置了其他过滤规则）                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 7. QQ Bot

### 7.1 认证机制

| 场景           | 认证方式     | 特殊机制           |
| -------------- | ------------ | ------------------ |
| **私聊 (C2C)** | 所有私聊消息 | 需要申请权限       |
| **群聊**       | 仅 @消息     | Bot 必须被添加到群 |

### 7.2 消息类型

```
QQ Bot 的消息类型：

┌─────────────────────────────────────────────────────────────────────────────┐
│  C2C (私聊)                                                                  │
│  ✅ 接收所有私聊消息                                                        │
│  ⚠️ 需要在开放平台申请 C2C 消息接收权限                                    │
│                                                                             │
│  GROUP (群聊)                                                               │
│  ✅ 仅接收 @Bot 的消息                                                      │
│  ❌ 不接收普通群聊消息（平台限制）                                          │
│  ⚠️ Bot 必须被添加到群才能接收消息                                          │
│                                                                             │
│  GUILD (频道)                                                               │
│  ✅ 接收频道消息                                                            │
│  需要订阅相关事件                                                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 7.3 场景举例

#### 场景 A：私聊 - 需要申请权限

```
配置：
{
  channels: {
    qqbot: {
      appId: "123456",
      clientSecret: "xxx",
      // OpenClaw 层面配置
      dmPolicy: "allowlist",
      allowFrom: ["123456789"],  // QQ 号
    },
  },
}

QQ 开放平台配置：
- 需要申请 "消息接收" 权限
- 需要 Intents 包含 C2C_MESSAGE_CREATE

用户 QQ号 123456789 私聊 Bot：
┌─────────────────────────────────────────────────────────────────────────────┐
│  用户: 你好                                                                  │
│  Bot: 你好！有什么可以帮助你的？                                            │
└─────────────────────────────────────────────────────────────────────────────┘

用户 QQ号 987654321 (不在白名单) 私聊 Bot：
┌─────────────────────────────────────────────────────────────────────────────┐
│  用户: 你好                                                                  │
│  Bot: (不响应，用户不在白名单)                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 10. 对比总结

### 10.1 私聊认证对比

| 平台         | 平台层面认证     | OpenClaw 层面认证              | 特殊限制          |
| ------------ | ---------------- | ------------------------------ | ----------------- |
| **飞书**     | 无               | dmPolicy + allowFrom + pairing | 支持配对机制      |
| **Telegram** | 无               | 无（所有私聊都接收）           | 无                |
| **Discord**  | 用户可能关闭私信 | 无                             | 需要用户允许私信  |
| **Slack**    | 无               | 无                             | 需要通过 App Home |
| **WhatsApp** | 无               | dmPolicy + allowFrom + pairing | 账号模式          |
| **QQ Bot**   | 需要申请权限     | allowFrom                      | 需要权限申请      |
| **Signal**   | 无               | dmPolicy + allowFrom           | 账号模式          |
| **企业微信** | 应用配置         | 无                             | 不支持私聊 Bot    |

### 10.2 群聊认证对比

| 平台         | 平台层面限制   | OpenClaw 层面认证        | @提及要求             |
| ------------ | -------------- | ------------------------ | --------------------- |
| **飞书**     | 无             | groupPolicy + 两层白名单 | 可配置 requireMention |
| **Telegram** | Privacy Mode   | groupPolicy + 白名单     | 默认需要 @ 或命令     |
| **Discord**  | Intents + 权限 | groupPolicy + 白名单     | 可配置                |
| **Slack**    | Event 订阅     | groupPolicy + 白名单     | 默认需要 @            |
| **WhatsApp** | 账号必须在群内 | groupPolicy + 白名单     | 无 @ 机制             |
| **QQ Bot**   | 仅 @消息       | groupPolicy + 白名单     | 平台强制              |
| **Signal**   | 账号必须在群内 | groupPolicy + 白名单     | 无 @ 机制             |
| **企业微信** | Webhook 单向   | 无                       | 不支持接收            |

### 10.3 关键差异图示
