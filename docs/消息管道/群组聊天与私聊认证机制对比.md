# 群组聊天与私聊认证机制对比

## 1. 概述

群组聊天和私聊在认证机制上有显著差异。这些差异源于两种场景的不同安全模型、使用模式和平台设计理念。

---

### 2.2 认证维度对比

| 维度             | 私聊认证         | 群聊认证                       |
| ---------------- | ---------------- | ------------------------------ |
| **认证对象**     | 单个用户         | 群组 + 群内用户                |
| **策略配置**     | dmPolicy         | groupPolicy                    |
| **白名单层级**   | 一层 (allowFrom) | 两层 (群白名单 + 发送者白名单) |

| **配对机制**     | 支持             | 不支持                         |
| **会话作用域**   | 用户维度         | 群组/话题维度                  |

### 3.2 dmPolicy 策略详解

#### 3.2.1 open - 开放模式

```json5
{
  channels: {
    feishu: {
      dmPolicy: "open", // 所有人都可以私聊
    },
  },
}
```

**特点**：

- 任何用户都可以发起私聊
- 无需任何授权
- 适合公开服务

**风险**：

- 可能被滥用
- 无法控制用户量
- API 调用成本不可控

#### 3.2.2 allowlist - 白名单模式

```json5
{
  channels: {
    feishu: {
      dmPolicy: "allowlist",
      allowFrom: [
        "ou_user1", // 用户 ID
        "ou_user2",
      ],
    },
  },
}
```

**特点**：

- 只有白名单中的用户可以私聊
- 需要手动维护白名单
- 适合企业内部使用

**检查逻辑**：

```typescript
function checkDmAllowlist(params: { senderId: string; allowFrom: string[] }): boolean {
  const { senderId, allowFrom } = params;

  // 空白名单 = 拒绝所有
  if (allowFrom.length === 0) {
    return false;
  }

  // 通配符 = 允许所有
  if (allowFrom.includes("*")) {
    return true;
  }

  // 精确匹配
  return allowFrom.includes(senderId);
}
```

#### 3.2.3 pairing - 配对模式（推荐）

```json5
{
  channels: {
    feishu: {
      dmPolicy: "pairing", // 默认策略
    },
  },
}
```

**特点**：

- 用户首次私聊需要获取配对码
- 管理员批准后才能使用
- 安全性最高
- 适合个人助理场景

**配对流程**：

### 3.3 私聊认证代码实现

```typescript
async function handleDirectMessageAuth(params: {
  senderId: string;
  senderName?: string;
  dmPolicy: string;
  allowFrom: string[];
  pairing: PairingController;
  sendMessage: (text: string) => Promise<void>;
}): Promise<{ allowed: boolean }> {
  const { senderId, dmPolicy, allowFrom, pairing, sendMessage } = params;

  // 1. open 模式：直接通过
  if (dmPolicy === "open") {
    return { allowed: true };
  }

  // 2. disabled 模式：直接拒绝
  if (dmPolicy === "disabled") {
    return { allowed: false };
  }

  // 3. 检查白名单
  const configAllowFrom = allowFrom.includes("*") || allowFrom.includes(senderId);

  // 4. 检查配对白名单（存储在文件中）
  const storeAllowFrom = await pairing.readAllowFromStore();
  const inStoreAllowFrom = storeAllowFrom.includes(senderId);

  // 5. allowlist 模式：只在配置白名单中检查
  if (dmPolicy === "allowlist") {
    return { allowed: configAllowFrom };
  }

  // 6. pairing 模式：检查配置白名单或配对白名单
  if (dmPolicy === "pairing") {
    if (configAllowFrom || inStoreAllowFrom) {
      return { allowed: true };
    }

    // 未配对，发送配对码
    await pairing.issueChallenge({
      senderId,
      sendPairingReply: sendMessage,
    });

    return { allowed: false };
  }

  return { allowed: false };
}
```

### 4.2 群聊认证的核心差异

#### 4.2.1 两层白名单

```
┌─────────────────────────────────────────────────────────────────────────────┐

│                                                                             │
│  私聊：只需要检查用户白名单                                                  │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
```

### 4.3 群聊认证代码实现

```typescript
async function handleGroupMessageAuth(params: {
  chatId: string;
  senderId: string;
  senderName?: string;
  mentionedBot: boolean;
  groupPolicy: string;
  groupAllowFrom: string[];
  allowFrom: string[];
  groupConfig?: GroupConfig;
  recordPendingHistory: () => void;
}): Promise<{ allowed: boolean }> {
  const {
    chatId,
    senderId,
    mentionedBot,
    groupPolicy,
    groupAllowFrom,
    allowFrom,
    groupConfig,
    recordPendingHistory,
  } = params;

  // 1. 检查群组策略
  if (groupPolicy === "disabled") {
    return { allowed: false };
  }

  // 2. 检查群组白名单
  if (groupPolicy === "allowlist") {
    // 检查群组
    const groupAllowed = groupAllowFrom.includes("*") || groupAllowFrom.includes(chatId);
    if (!groupAllowed) {
      return { allowed: false };
    }

    // 检查发送者（可使用群组特定的白名单）
    const senderAllowFrom = groupConfig?.allowFrom ?? allowFrom;
    const senderAllowed = senderAllowFrom.includes("*") || senderAllowFrom.includes(senderId);
    if (!senderAllowed) {
      return { allowed: false };
    }
  }

  // 3. 检查是否需要提及
  const requireMention = resolveRequireMention({
    groupPolicy,
    groupConfig,
  });

  if (requireMention && !mentionedBot) {
    // 记录到历史但不处理
    recordPendingHistory();
    return { allowed: false };
  }

  return { allowed: true };
}
```

```
└─────────────────────────────────────────────────────────────────────────────┘
```

## 10. 总结

### 10.1 核心差异总结

| 维度           | 私聊认证             | 群聊认证              |
| -------------- | -------------------- | --------------------- |
| **认证对象**   | 单个用户             | 群组 + 群内用户       |
| **策略配置**   | dmPolicy (4种)       | groupPolicy (3种)     |
| **白名单层级** | 一层                 | 两层（群组 + 用户）   |
| **配对机制**   | 支持                 | 不支持                |
| **提及要求**   | 不适用               | 支持 (requireMention) |
| **会话作用域** | 用户维度             | 群组/话题维度         |
| **失败行为**   | 发送配对码或静默     | 静默或记录历史        |
| **设计理念**   | 用户为中心、灵活授权 | 群组为中心、防止打扰  |

### 10.2 一句话总结

**私聊认证关注"谁可以使用 Bot"，群聊认证关注"哪个群组的哪些人在什么情况下可以使用 Bot"。**
