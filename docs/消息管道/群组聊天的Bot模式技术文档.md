# 群组聊天的 Bot 模式技术文档

## 1. 概述

不同即时通讯平台在群组聊天中对 Bot 的依赖程度不同。本文档分析各平台的群聊架构，解释为什么有的平台必须使用 Bot，而有的平台不需要。

---

## 2. 平台分类

### 2.1 按群聊 Bot 需求分类

| 类别           | 平台            | 群聊是否需要 Bot | 实现方式         |
| -------------- | --------------- | ---------------- | ---------------- |
| **Bot 必需**   | 飞书            | ✅ 需要          | 官方机器人 API   |
|                | Telegram        | ✅ 需要          | Bot API          |
|                | Discord         | ✅ 需要          | Bot Gateway      |
|                | Slack           | ✅ 需要          | App/Bot API      |
|                | QQ Bot          | ✅ 需要          | 官方 Bot API     |
|                | Microsoft Teams | ✅ 需要          | Bot Framework    |
|                | 企业微信        | ✅ 需要          | 群机器人 Webhook |
| **Bot 非必需** | WhatsApp        | ❌ 不需要        | 个人账号登录     |
|                | Signal          | ❌ 不需要        | 个人账号登录     |
|                | iMessage        | ❌ 不需要        | 个人账号         |
|                | 微信个人号      | ❌ 不需要        | 个人账号登录     |
|                | Zalo            | ❌ 不需要        | 个人账号登录     |

## 3. Bot 模式详解

### 3.1 模式 A：Bot 必需模式

#### 3.1.1 架构图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Bot 必需模式架构                                                            │
│                                                                             │
│  群组                                                                       │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  用户 A: 大家好                                                      │   │
│  │  用户 B: @Bot 帮我查一下天气                                         │   │
│  │  Bot: [AI 回复] 今天天气晴朗，气温 28°C...                          │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  流程：                                                                     │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  1. 开发者在平台创建 Bot 应用                                        │   │
│  │  2. 获取 Bot 凭证 (Token / App ID + Secret)                         │   │
│  │  3. 将 Bot 添加到群组                                                │   │
│  │  4. 用户在群内 @Bot 或发送命令                                       │   │
│  │  5. 平台通过 Webhook/WebSocket 推送消息给 Bot                       │   │
│  │  6. Bot (OpenClaw) 处理消息并调用平台 API 回复                      │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  关键点：Bot 是消息的"接收端点"和"发送端点"                                 │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 3.1.2 消息流转

```
用户发送消息
     │
     ▼
┌─────────────┐
│   平台群组   │
│   服务器     │
└──────┬──────┘
       │
       │ 检查是否需要推送给 Bot
       │ - 是否 @Bot？
       │ - Bot 是否有权限接收所有消息？
       │
       ▼
┌─────────────┐
│  平台 API   │
│  推送服务   │
└──────┬──────┘
       │
       │ Webhook / WebSocket
       │
       ▼
┌─────────────┐
│    Bot      │
│ (OpenClaw)  │
│             │
│ 1. 验证签名 │
│ 2. 解析消息 │
│ 3. 调用 AI  │
│ 4. 发送回复 │
└─────────────┘
```

## 4. 两种模式对比

### 4.1 功能对比

| 特性               | Bot 模式           | 个人账号模式         |
| ------------------ | ------------------ | -------------------- |
| **身份显示**       | Bot 名称/头像      | 个人账号名称/头像    |
| **消息接收范围**   | 可配置（隐私模式） | 所有消息             |
| **是否需要 @提及** | 通常需要（可配置） | 不需要               |
| **封号风险**       | 无（官方 API）     | 有（非官方协议）     |
| **功能限制**       | 受平台 API 限制    | 较少（模拟真实用户） |
| **合规性**         | 完全合规           | 可能存在合规风险     |
| **稳定性**         | 高（官方维护）     | 低（协议可能变更）   |
| **成本**           | 可能有 API 费用    | 通常免费             |

### 4.2 适用场景

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Bot 模式适用场景                                                            │
│                                                                             │
│  ✅ 企业应用                                                                │
│     - 需要稳定、合规的服务                                                  │
│     - 需要明确的 Bot 身份                                                  │
│     - 需要官方 API 支持                                                    │
│                                                                             │
│  ✅ 公开服务                                                                │

└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  个人账号模式适用场景                                                        │

## 5. 为什么飞书需要 Bot？

### 5.1 飞书群聊架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  飞书群聊消息架构                                                            │
│                                                                             │
│  核心原则：飞书群组不向任何第三方推送消息，只有"机器人"能接收消息。          │
│                                                                             │
│  消息流：                                                                    │
│                                                                             │
│  ┌─────────┐                                                                │
│  │  用户   │ ──▶ 消息 ──▶ ┌─────────────────────────────┐                   │
│  └─────────┘              │         群组                 │                   │
│                           │                             │                   │
│  ┌─────────┐              │   消息存储在群组服务器      │                   │
│  │  用户   │ ──▶ 消息 ──▶ │                             │                   │
│  └─────────┘              │   ┌─────────────────────┐   │                   │
│                           │   │ 消息分发逻辑        │   │                   │
│                           │   │                     │   │                   │
│                           │   │ - 存储消息          │   │                   │
│                           │   │ - 推送给在线成员    │   │                   │
│                           │   │ - 推送给机器人      │   │                   │
│                           │   └──────────┬──────────┘   │                   │
│                           └──────────────┼──────────────┘                   │
│                                          │                                  │
│                           ┌──────────────┴──────────────┐                   │
│                           │                             │                   │
│                           ▼                             ▼                   │
│                    ┌─────────────┐              ┌─────────────┐             │
│                    │  普通用户   │              │   机器人    │             │
│                    │ (客户端)    │              │ (OpenClaw)  │             │
│                    └─────────────┘              └─────────────┘             │
│                           │                             │                   │
│                           │                             │                   │
│                    普通消息推送                  事件订阅推送               │
│                    (WebSocket)                   (Webhook/WebSocket)        │
│                                                                             │
│  没有 Bot = 没有消息出口                                                    │
│  OpenClaw 无法"加入群组"成为普通成员（飞书不提供此能力）                     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 6. 为什么 WhatsApp 不需要 Bot？

### 6.1 WhatsApp 架构

```

│  WhatsApp 群聊消息架构                                                       │
│                                                                             │

│                                                                             │
│  消息流：                                                                    │
│                                                                             │
│  ┌─────────┐                                                                │
│  │  用户   │ ──▶ 加密消息 ──▶ ┌─────────────────────────────┐              │
│  └─────────┘                  │         群组                 │              │
│                               │                             │              │
│  ┌─────────────────────────┐  │   端到端加密消息存储        │              │
│  │  OpenClaw "账号"        │  │                             │              │
│  │  (模拟 WhatsApp 客户端) │  │   ┌─────────────────────┐   │              │
│  │                         │  │   │ 消息分发逻辑        │   │              │

│  │  - 接收所有消息         │  │   │ - 解密消息          │   │              │

│  │                         │  │   └──────────┬──────────┘   │              │

│           │                                   │                              │
│           │                                   │                              │
│           ◀───────────────────────────────────┘                              │
│           │                                                                  │
│           │ 所有消息推送给每个成员                                           │
│           │ (包括 OpenClaw 账号)                                             │
│           │                                                                  │
│  OpenClaw 账号 = 普通群成员                                                  │

### 8.2 风险提示

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  使用个人账号模式的风险                                                      │
│                                                                             │

│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  - 平台可能检测到非官方客户端行为                                    │   │
│  │  - 账号可能被临时或永久封禁                                          │   │
│  │  - 封号后无法恢复数据                                                │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  2. 合规风险                                                                │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  - 可能违反平台服务条款                                              │   │
│  │  - 可能涉及用户隐私问题                                              │   │
│  │  - 可能不符合企业合规要求                                            │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  3. 稳定性风险                                                              │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  - 协议变更可能导致服务中断                                          │   │
│  │  - 需要持续维护协议适配                                              │   │
│  │  - 第三方库可能停止更新                                              │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  建议：                                                                      │
│  - 企业应用优先选择 Bot 模式                                                │
│  - 个人使用可接受个人账号模式                                               │
│  - 做好账号备份和迁移计划                                                   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 9. 总结

### 9.1 核心结论

| 问题                       | 答案                                    |
| -------------------------- | --------------------------------------- |
| 群聊必须要有 Bot 吗？      | **不一定**，取决于平台架构              |
| 飞书群聊需要 Bot 吗？      | **需要**，飞书只通过 Bot 推送消息       |
| WhatsApp 群聊需要 Bot 吗？ | **不需要**，OpenClaw 账号就是普通群成员 |
| 为什么不同平台不一样？     | 各平台 API 设计和安全架构不同           |

### 9.2 平台架构决定实现方式

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  平台架构 → 实现方式                                                         │
│                                                                             │
│  有官方 Bot API                                                            │
│       │                                                                     │
│       └──▶ Bot 模式                                                        │
│           - 飞书、Telegram、Discord、Slack、QQ Bot、企业微信                │
│           - Bot 是消息端点                                                 │
│           - 官方支持、稳定合规                                             │
│                                                                             │
│  无官方 Bot API                                                            │
│       │                                                                     │
│       └──▶ 个人账号模式                                                    │
│           - WhatsApp、Signal、iMessage                                     │
│           - 账号是普通群成员                                               │
│           - 非官方协议、存在风险                                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```
