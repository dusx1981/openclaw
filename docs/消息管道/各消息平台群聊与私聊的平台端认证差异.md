# 各消息平台群聊与私聊的平台端认证差异

## 1. 概述

平台端认证是**平台验证 OpenClaw 应用身份**的过程，区别于 OpenClaw 端认证（验证用户权限）。

本文档重点说明：

- 各平台在群聊和私聊场景下的认证差异
- 权限申请的差异
- 事件订阅的差异
- 认证凭证的差异

---

## 2. 平台端认证对比总览

| 平台         | 私聊认证凭证    | 群聊认证凭证        | 权限差异              | 认证是否相同 |
| ------------ | --------------- | ------------------- | --------------------- | ------------ |
| **飞书**     | App ID + Secret | App ID + Secret     | 无差异                | ✅ 相同      |
| **Telegram** | Bot Token       | Bot Token           | Privacy Mode 差异     | ✅ 凭证相同  |
| **Discord**  | Bot Token       | Bot Token + Intents | **需额外申请 Intent** | ❌ 权限不同  |
| **Slack**    | Bot Token       | Bot Token           | Event 订阅差异        | ✅ 凭证相同  |
| **WhatsApp** | Session (QR)    | Session (QR)        | 账号必须在群内        | ✅ 相同      |
| **QQ Bot**   | App ID + Secret | App ID + Secret     | **需分别申请权限**    | ❌ 权限不同  |
| **Signal**   | Phone + Device  | Phone + Device      | 账号必须在群内        | ✅ 相同      |
| **企业微信** | -               | Webhook Key         | 仅支持群聊            | N/A          |

## 3. 飞书 (Feishu/Lark)

### 3.1 平台端认证架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  飞书平台端认证                                                              │
│                                                                             │
│  认证凭证：                                                                  │
│  - App ID: cli_xxxxxxxxxxxxx                                               │
│  - App Secret: xxxxxxxxxxxxxxxx                                            │
│                                                                             │
│  私聊和群聊使用相同的凭证！                                                  │
│                                                                             │
│  认证流程：                                                                  │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  1. 使用 App ID + Secret 获取 tenant_access_token                   │   │
│  │  2. 调用 API 时携带此 Token                                         │   │
│  │  3. 接收事件时验证签名 (encryptKey)                                  │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  差异在于事件订阅配置，而非认证凭证：                                        │
│  - 私聊：im.message.receive_v1 (chat_type = "p2p")                        │
│  - 群聊：im.message.receive_v1 (chat_type = "group")                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 权限申请

```
飞书开放平台权限配置：

┌─────────────────────────────────────────────────────────────────────────────┐
│  权限配置（私聊和群聊相同）                                                  │
│                                                                             │
│  必需权限：                                                                  │
│  - im:message                    # 获取与发送消息                          │
│  - im:message:send_as_bot        # 以应用身份发消息                        │
│  - im:message:receive_as_bot     # 接收消息事件                            │
│                                                                             │
│  可选权限：                                                                  │
│  - im:chat                      # 获取群组信息                             │
│  - im:chat:readonly             # 读取群组信息                             │
│  - contact:user.base:readonly   # 获取用户基本信息                         │
│                                                                             │
│  注意：私聊和群聊使用相同的权限配置，无需分别申请。                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 场景举例

```json5
// 配置示例
{
  channels: {
    feishu: {
      appId: "cli_xxxxxxxxx",
      appSecret: "xxxxxxxxxx",
      // 私聊和群聊使用相同的凭证
      encryptKey: "xxx",  // 用于验证 Webhook 签名
      verificationToken: "xxx",

      // 事件订阅配置（相同）
      events: [
        "im.message.receive_v1",  // 同时接收私聊和群聊消息
      ],
    },
  },
}

// 平台推送事件
{
  "type": "im.message.receive_v1",
  "event": {
    "message": {
      "chat_type": "p2p",  // 私聊
      // 或 "chat_type": "group",  // 群聊
    },
  },
}

// OpenClaw 根据 chat_type 判断是私聊还是群聊
// 认证凭证完全相同
```

## 4. Telegram

### 4.1 平台端认证架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Telegram 平台端认证                                                         │
│                                                                             │
│  认证凭证：                                                                  │
│  - Bot Token: 123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11                   │
│                                                                             │
│  私聊和群聊使用相同的 Token！                                                │
│                                                                             │
│  Token 结构：                                                                │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  123456 : ABC-DEF1234ghIkl-zyx57W2v1u123ew11                       │   │
│  │  Bot ID    Bot Token (用于认证所有 API 调用)                        │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  差异在于 Privacy Mode（平台层面的消息过滤）：                               │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Privacy Mode = ON (默认)                                           │   │
│  │  - 私聊：接收所有消息 ✅                                            │   │
│  │  - 群聊：仅接收 @Bot 或 /命令 ⚠️                                   │   │
│  │                                                                     │   │
│  │  Privacy Mode = OFF                                                 │   │
│  │  - 私聊：接收所有消息 ✅                                            │   │
│  │  - 群聊：接收所有消息 ✅ (需 Bot 是管理员)                          │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 Privacy Mode 详解

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Telegram Privacy Mode 配置                                                 │
│                                                                             │
│  配置方式：向 @BotFather 发送 /setprivacy                                   │
│                                                                             │
│  Privacy Mode = ON (默认)：                                                 │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  私聊消息：                                                          │   │
│  │  ┌─────────────────────────────────────────────────────────────┐   │   │
│  │  │  用户: 你好                                                  │   │   │
│  │  │  Bot: 接收 ✅                                                │   │   │
│  │  │                                                              │   │   │
│  │  │  用户: 今天天气怎么样                                        │   │   │
│  │  │  Bot: 接收 ✅                                                │   │   │
│  │  └─────────────────────────────────────────────────────────────┘   │   │
│  │                                                                      │   │
│  │  群聊消息：                                                          │   │
│  │  ┌─────────────────────────────────────────────────────────────┐   │   │
│  │  │  用户 A: 大家好                                              │   │   │
│  │  │  Bot: 不接收 ❌ (平台过滤)                                   │   │   │
│  │  │                                                              │   │   │
│  │  │  用户 B: 今天天气怎么样                                      │   │   │
│  │  │  Bot: 不接收 ❌ (平台过滤)                                   │   │   │
│  │  │                                                              │   │   │
│  │  │  用户 A: @MyBot 你好                                         │   │   │
│  │  │  Bot: 接收 ✅ (@提及)                                        │   │   │
│  │  │                                                              │   │   │
│  │  │  用户 B: /weather                                            │   │   │
│  │  │  Bot: 接收 ✅ (/命令)                                        │   │   │
│  │  └─────────────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  Privacy Mode = OFF：                                                       │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  要求：Bot 必须是群管理员                                           │   │
│  │                                                                      │   │
│  │  私聊消息：                                                          │   │
│  │  - 接收所有消息 ✅                                                  │   │
│  │                                                                      │   │
│  │  群聊消息：                                                          │   │
│  │  - 接收所有消息 ✅ (平台不再过滤)                                   │   │
│  │  - 然后由 OpenClaw 层面决定是否处理                                 │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 场景举例

```json5
// 配置示例
{
  channels: {
    telegram: {
      botToken: "123456:ABC-DEF...",  // 私聊和群聊使用相同的 Token

      // 无需额外配置，Privacy Mode 由 @BotFather 控制
      // OpenClaw 自动适应 Privacy Mode
    },
  },
}

// API 调用示例（私聊和群聊相同）
// 发送私聊消息
POST https://api.telegram.org/bot{token}/sendMessage
{
  "chat_id": 123456789,  // 用户 ID
  "text": "你好！"
}

// 发送群聊消息
POST https://api.telegram.org/bot{token}/sendMessage
{
  "chat_id": -1001234567890,  // 群组 ID (负数)
  "text": "大家好！"
}

// 认证方式完全相同：都在 URL 中包含 Bot Token
```

## 5. Discord

### 5.1 平台端认证架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Discord 平台端认证                                                          │
│                                                                             │
│  认证凭证：                                                                  │
│  - Bot Token: MTk4NjIyNDgzNDc...                                          │
│                                                                             │
│  私聊和群聊使用相同的 Token，但需要不同的 Gateway Intents！                  │
│                                                                             │
│  Gateway Intents (意图)：                                                   │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  私聊必需：                                                          │   │
│  │  - DIRECT_MESSAGES          # 接收私信事件                           │   │
│  │  - MESSAGE_CONTENT          # 读取消息内容 (特权)                   │   │
│  │                                                                      │   │
│  │  群聊必需：                                                          │   │
│  │  - GUILDS                   # 服务器事件                             │   │
│  │  - GUILD_MESSAGES           # 服务器消息事件                         │   │
│  │  - MESSAGE_CONTENT          # 读取消息内容 (特权) ⚠️                │   │
│  │                                                                      │   │
│  │  ⚠️ MESSAGE_CONTENT 是特权 Intent，需要在开发者面板申请！           │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.2 特权 Intent 申请

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Discord 特权 Intent 申请流程                                               │
│                                                                             │
│  背景：                                                                      │
│  Discord 为了保护用户隐私，限制 Bot 读取消息内容的能力。                    │
│  MESSAGE_CONTENT Intent 是"特权 Intent"，需要单独申请。                    │
│                                                                             │
│  申请步骤：                                                                  │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  1. 进入 Discord Developer Portal                                   │   │
│  │     https://discord.com/developers/applications                     │   │
│  │                                                                      │   │
│  │  2. 选择你的应用 → Bot → Privileged Gateway Intents                │   │
│  │                                                                      │   │
│  │  3. 勾选需要的 Intents：                                            │   │
│  │     ☑️ PRESENCE INTENT                                              │   │
│  │     ☑️ SERVER MEMBERS INTENT                                        │   │
│  │     ☑️ MESSAGE CONTENT INTENT  ← 这是关键！                         │   │
│  │                                                                      │   │
│  │  4. 保存更改                                                         │   │
│  │                                                                      │   │
│  │  5. 如果 Bot 已在服务器中，需要重新邀请 Bot                          │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  注意：                                                                      │
│  - 没有 MESSAGE_CONTENT Intent，Bot 无法读取消息内容                       │
│  - 私聊和群聊都需要此 Intent                                               │
│  - 验证的 Bot (100+ 服务器) 可自动获得，未验证的需要申请                   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.3 场景举例

```json5
// 配置示例
{
  channels: {
    discord: {
      token: "MTk4NjIyNDgzNDc...",  // Bot Token

      // Gateway Intents 配置
      intents: [
        "GUILDS",                    // 服务器事件 (群聊需要)
        "GUILD_MESSAGES",            // 服务器消息 (群聊需要)
        "DIRECT_MESSAGES",           // 私信事件 (私聊需要)
        "MESSAGE_CONTENT",           // 消息内容 (都需要，特权)
      ],

      // Bot 权限配置 (OAuth2)
      permissions: [
        "SendMessages",
        "ReadMessageHistory",
        "MentionEveryone",
      ],
    },
  },
}

// Gateway 连接示例
const ws = new WebSocket("wss://gateway.discord.gg/?v=10&encoding=json");

// 发送 Identify (认证)
{
  "op": 2,
  "d": {
    "token": "MTk4NjIyNDgzNDc...",
    "intents": 513,  // GUILD_MESSAGES | DIRECT_MESSAGES | MESSAGE_CONTENT
    "properties": {
      "$os": "linux",
      "$browser": "openclaw",
      "$device": "openclaw"
    }
  }
}

// 接收事件
// 私聊事件
{
  "t": "MESSAGE_CREATE",
  "d": {
    "channel_id": "123456789",  // 私信频道
    "guild_id": null,           // 无服务器 ID = 私聊
    "content": "你好"
  }
}

// 群聊事件
{
  "t": "MESSAGE_CREATE",
  "d": {
    "channel_id": "987654321",  // 服务器频道
    "guild_id": "111222333",    // 有服务器 ID = 群聊
    "content": "大家好"
  }
}
```

## 6. Slack

### 6.1 平台端认证架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Slack 平台端认证                                                            │
│                                                                             │
│  认证凭证：                                                                  │
│  - Bot Token (xoxb-...): 用于调用 API                                      │
│  - App Token (xapp-...): 用于 Socket Mode (可选)                           │
│                                                                             │
│  私聊和群聊使用相同的凭证，但需要订阅不同的事件！                            │
│                                                                             │
│  事件订阅：                                                                  │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  私聊事件：                                                          │   │
│  │  - message.im              # 私信消息                                │   │
│  │  - message.mpim           # 多人私信消息                             │   │
│  │                                                                      │   │
│  │  群聊事件：                                                          │   │
│  │  - message.channels       # 公开频道消息                             │   │
│  │  - message.groups         # 私有频道消息                             │   │
│  │  - app_mention            # Bot 被提及                               │   │
│  │                                                                      │   │
│  │  注意：需要在 Slack App 配置中分别订阅这些事件                       │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.2 事件订阅配置

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Slack App 配置                                                              │
│                                                                             │
│  在 Slack API 控制台配置：                                                   │
│  https://api.slack.com/apps/{app_id}                                       │
│                                                                             │
│  1. OAuth & Permissions:                                                    │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Bot Token Scopes:                                                   │   │
│  │  - chat:write             # 发送消息                                 │   │
│  │  - im:history             # 读取私信历史 (私聊需要)                  │   │
│  │  - channels:history       # 读取频道历史 (群聊需要)                  │   │
│  │  - groups:history         # 读取私有频道历史 (群聊需要)              │   │
│  │  - mpim:history           # 读取多人私信历史 (私聊需要)              │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  2. Event Subscriptions:                                                    │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Subscribe to bot events:                                            │   │
│  │  - message.im              ✅ 私聊需要                               │   │
│  │  - message.mpim           ✅ 多人私信需要                             │   │
│  │  - message.channels       ✅ 群聊需要                                │   │
│  │  - message.groups         ✅ 群聊需要                                │   │
│  │  - app_mention            ✅ 群聊需要 (@提及)                        │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  3. Socket Mode (推荐)：                                                    │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  - 启用 Socket Mode                                                  │   │
│  │  - 生成 App Token (xapp-...)                                        │   │
│  │  - 无需公网 IP                                                       │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 6.3 场景举例

```json5
// 配置示例
{
  channels: {
    slack: {
      mode: "socket",  // Socket Mode
      appToken: "xapp-1-A039K...",  // Socket Mode 需要
      botToken: "xoxb-123456789012-...",  // API 调用需要

      // 无需配置事件订阅，在 Slack API 控制台配置
    },
  },
}

// Socket Mode 连接
const ws = new WebSocket("wss://wss-primary.slack.com/socket/websocket");

// 接收事件
// 私聊事件
{
  "type": "events_api",
  "payload": {
    "event": {
      "type": "message",
      "channel_type": "im",  // 私信
      "user": "U123456",
      "text": "你好"
    }
  }
}

// 群聊事件
{
  "type": "events_api",
  "payload": {
    "event": {
      "type": "message",
      "channel_type": "channel",  // 频道
      "channel": "C123456",
      "user": "U123456",
      "text": "大家好"
    }
  }
}

// @提及事件
{
  "type": "events_api",
  "payload": {
    "event": {
      "type": "app_mention",  // Bot 被提及
      "channel": "C123456",
      "user": "U123456",
      "text": "<@U123456> 你好"
    }
  }
}
```

## 7. WhatsApp

### 7.1 平台端认证架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  WhatsApp 平台端认证                                                         │
│                                                                             │
│  认证方式：个人账号模式 (非 Bot API)                                        │
│                                                                             │
│  认证凭证：                                                                  │
│  - Session (通过 QR 码登录获得)                                             │
│  - 包含：认证密钥、设备信息等                                               │
│                                                                             │
│  私聊和群聊使用相同的 Session！                                             │
│                                                                             │
│  核心差异：                                                                  │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  私聊：                                                               │   │
│  │  - Session 自动接收发给账号的所有私聊消息                            │   │
│  │  - 无需额外配置                                                       │   │
│  │                                                                      │   │
│  │  群聊：                                                               │   │
│  │  - Session 对应的账号必须被邀请加入群组                               │   │
│  │  - 只有在群内的账号才能接收群消息                                     │   │
│  │  - 如果账号不在群内，无法接收任何群消息                               │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  这是 WhatsApp 架构决定的，不是权限配置差异。                               │

## 11. 对比总结

### 11.1 认证凭证对比

| 平台         | 私聊凭证        | 群聊凭证        | 是否相同 |
| ------------ | --------------- | --------------- | -------- |
| **飞书**     | App ID + Secret | App ID + Secret | ✅ 相同  |
| **Telegram** | Bot Token       | Bot Token       | ✅ 相同  |
| **Discord**  | Bot Token       | Bot Token       | ✅ 相同  |
| **Slack**    | Bot Token       | Bot Token       | ✅ 相同  |
| **WhatsApp** | Session         | Session         | ✅ 相同  |
| **Signal**   | Phone + Device  | Phone + Device  | ✅ 相同  |
| **QQ Bot**   | App ID + Secret | App ID + Secret | ✅ 相同  |
| **企业微信** | 企业应用凭证    | Webhook Key     | ❌ 不同  |

### 11.2 权限/订阅差异对比

| 平台         | 私聊权限/订阅          | 群聊权限/订阅                    | 是否需要分别申请    |
| ------------ | ---------------------- | -------------------------------- | ------------------- |
| **飞书**     | im.message 事件        | im.message 事件                  | ❌ 相同配置         |
| **Telegram** | 无                     | Privacy Mode 配置                | ❌ 平台配置         |
| **Discord**  | DIRECT_MESSAGES Intent | GUILD_MESSAGES + MESSAGE_CONTENT | ✅ **需要分别申请** |
| **Slack**    | message.im 事件        | message.channels + app_mention   | ✅ **需要分别订阅** |
| **WhatsApp** | 自动接收               | 账号必须在群内                   | ❌ 架构差异         |
| **Signal**   | 自动接收               | 账号必须在群内                   | ❌ 架构差异         |
| **QQ Bot**   | C2C_MESSAGE_CREATE     | GROUP_AT_MESSAGE_CREATE          | ✅ **需要分别申请** |
| **企业微信** | 企业应用权限           | Webhook (无权限)                 | ✅ 完全不同         |

### 11.3 核心差异总结

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  需要分别申请权限的平台                                                      │
│                                                                             │
│  Discord:                                                                   │

│  - 群聊需要 GUILD_MESSAGES + MESSAGE_CONTENT Intent                        │
│  - MESSAGE_CONTENT 是特权 Intent，必须申请                                 │
│                                                                             │
│  Slack:                                                                     │
│  - 私聊需要订阅 message.im 事件                                            │
│  - 群聊需要订阅 message.channels + app_mention 事件                        │
│  - 需要在开发者控制台分别配置                                              │
│                                                                             │
│  QQ Bot:                                                                    │
│  - 私聊需要申请 C2C_MESSAGE_CREATE 权限                                    │
│  - 群聊需要申请 GROUP_AT_MESSAGE_CREATE 权限                               │
│  - 必须在 QQ 开放平台分别申请                                              │
│                                                                             │
│  企业微信:                                                                   │
│  - 私聊使用企业微信应用                                                    │
│  - 群聊使用 Webhook                                                        │
│  - 完全不同的认证机制                                                      │
│                                                                             │

┌─────────────────────────────────────────────────────────────────────────────┐
│  使用相同凭证但平台行为不同的                                                │
│                                                                             │
│  Telegram:                                                                  │
│  - 相同 Bot Token                                                          │

│  - 默认只接收 @Bot 或 /命令                                                │

│  WhatsApp / Signal:                                                         │
│  - 相同 Session                                                             │

│  - 平台架构决定的限制                                                      │
│                                                                             │
│  飞书:                                                                       │

│  - 无平台层面差异                                                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
