# 数据采集失败降级机制设计

## 1. 概述

### 1.1 背景

数据采集模块需要从多个电商平台获取商品数据。每个平台可能有多个数据源（官方 API、第三方 API、爬虫），这些数据源的可用性和稳定性各不相同。当主要数据源失败时，需要有完善的降级机制保证系统可用性。

### 1.2 设计目标

| 目标 | 说明 | 优先级 |
|------|------|--------|
| **高可用性** | 单个数据源失败不影响整体服务 | P0 |
| **优雅降级** | 多层降级策略，保证数据可获取 | P0 |
| **成本优化** | 优先使用低成本数据源 | P1 |
| **故障隔离** | 故障数据源自动隔离，防止级联失败 | P1 |
| **自动恢复** | 故障数据源自动恢复探测 | P2 |

### 1.3 适用范围

- 平台适配器数据获取（`BasePlatformAdapter`）
- 数据管道过滤器（`FetchFilter`）
- 应用层用例（`FetchProductUseCase`）

```
┌─────────────────────────────────────────────────────────────────┐
│                        BasePlatformAdapter                       │

│  │                    getDataSource()                          │ │
│  │  ┌───────────┐  ┌───────────┐  ┌───────────┐               │ │
│  │  │  Source 1 │  │  Source 2 │  │  Source 3 │               │ │
│  │  │ (P=1)     │  │ (P=2)     │  │ (P=3)     │               │ │
│  │  └─────┬─────┘  └───────────┘  └───────────┘               │ │
│  │        │                                                    │ │
│  │        ▼                                                    │ │
│  │  只选择优先级最高的源，失败后不尝试其他源                     │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 现有机制

| 机制 | 实现位置 | 说明 |
|------|----------|------|
| 指数退避重试 | `BasePlatformAdapter.withRetry()` | 同一数据源重试 3 次 |
| 优先级选择 | `BasePlatformAdapter.getDataSource()` | 选择最高优先级可用源 |
| 配额检查 | `DataSource.hasRemainingQuota()` | 过滤无配额的数据源 |
| 过期检测 | `CacheProvider.get()` | 返回 `isStale` 标记 |

### 2.3 存在问题

| 问题 | 影响 | 严重程度 |
|------|------|----------|
| **无多源故障转移** | 主数据源失败后无备选方案 | 高 |
| **过期缓存被丢弃** | `isStale=true` 的数据被拒绝 | 高 |
| **无熔断器** | 故障源持续重试，资源浪费 | 中 |
| **无自动健康跟踪** | `markUnavailable()` 从未被调用 | 中 |
| **无成本感知** | `costPerCall` 未参与决策 | 低 |

## 3. 设计方案

### 3.1 整体架构

```
┌────────────────────────────────────────────────────────────────────────┐
│                          Degradation Layers                            │
│                                                                        │
│  Layer 1: Cache (Fresh)                                               │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Fresh Cache → 返回缓存数据                                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                          │ (miss)                                      │
│                          ▼                                             │
│  Layer 2: Database                                                     │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Database → 返回数据库数据                                       │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                          │ (miss)                                      │
│                          ▼                                             │
│  Layer 3: Data Sources (with Failover)                                │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Source 1 (P=1) → 重试 3 次 → 失败                              │   │
│  │         ↓                                                        │   │
│  │  Source 2 (P=2) → 重试 3 次 → 成功 ✓                            │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                          │ (all failed)                                │
│                          ▼                                             │
│  Layer 4: Stale Cache (Degraded)                                      │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  Stale Cache → 返回过期缓存数据（标记为降级模式）                  │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                          │ (no stale cache)                            │
│                          ▼                                             │
│  Layer 5: Error                                                        │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  返回错误，记录告警                                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 3.2 降级层级定义

```typescript
enum DegradationLevel {
  FRESH_CACHE = "fresh_cache",           // 层级 1: 新鲜缓存
  DATABASE = "database",                 // 层级 2: 数据库
  PRIMARY_SOURCE = "primary_source",     // 层级 3: 主数据源
  FALLBACK_SOURCE = "fallback_source",   // 层级 3: 备用数据源
  STALE_CACHE = "stale_cache",           // 层级 4: 过期缓存
  ERROR = "error",                       // 层级 5: 错误
}
```

#### 4.1.3 接口设计

```typescript
interface FetchWithFailoverOptions {
  preferredSource?: string;       // 首选数据源 ID
  maxSources?: number;           // 最多尝试的数据源数量
  skipSources?: string[];        // 跳过的数据源 ID 列表
  onSourceFailure?: (sourceId: string, error: Error) => void;  // 失败回调
}

interface FetchWithFailoverResult<T> {
  data: T;
  source: string;
  attempts: Array<{
    sourceId: string;
    success: boolean;
    error?: string;
    latencyMs: number;
  }>;
  totalLatencyMs: number;
  degradationLevel: DegradationLevel;
}
```

#### 4.1.4 实现伪代码

```typescript
async fetchWithFailover<T>(
  fn: (source: DataSource) => Promise<T>,
  options?: FetchWithFailoverOptions
): Promise<FetchWithFailoverResult<T>> {
  const attempts: FetchWithFailoverResult<T>['attempts'] = [];
  const start = Date.now();

  // 获取可用数据源列表（排除跳过的源）
  const sources = this.getAvailableSources()
    .filter(s => !options?.skipSources?.includes(s.id))
    .slice(0, options?.maxSources ?? 3);

  // 如果指定了首选源，放到最前面
  if (options?.preferredSource) {
    const preferred = sources.find(s => s.id === options.preferredSource);
    if (preferred) {
      sources.sort((a, b) => 
        a.id === options.preferredSource ? -1 : 
        b.id === options.preferredSource ? 1 : 0
      );
    }
  }

  let lastError: Error | null = null;

  for (const source of sources) {
    const attemptStart = Date.now();
    
    try {
      const data = await this.withRetry(() => fn(source));
      
      attempts.push({
        sourceId: source.id,
        success: true,
        latencyMs: Date.now() - attemptStart,
      });

      // 标记源可用
      this.updateDataSource(source.id, source.markAvailable().toData());
      
      return {
        data,
        source: source.id,
        attempts,
        totalLatencyMs: Date.now() - start,
        degradationLevel: sources.indexOf(source) === 0 
          ? DegradationLevel.PRIMARY_SOURCE 
          : DegradationLevel.FALLBACK_SOURCE,
      };
    } catch (error) {
      lastError = error instanceof Error ? error : new Error(String(error));
      
      attempts.push({
        sourceId: source.id,
        success: false,
        error: lastError.message,
        latencyMs: Date.now() - attemptStart,
      });

      // 回调通知
      options?.onSourceFailure?.(source.id, lastError);

      // 标记源失败（但不立即设为不可用，可能是临时故障）
      this.recordSourceFailure(source.id, lastError.message);
    }
  }

  throw lastError ?? new Error("No available data sources");
}
```

### 4.2 熔断器模式

#### 4.2.1 设计说明

防止对已经失败的数据源持续重试，自动熔断并在一段时间后尝试恢复。

#### 4.2.2 状态机

```
                    ┌─────────────────┐
                    │     CLOSED      │
                    │   (正常状态)     │
                    └────────┬────────┘
                             │
                             │ 连续失败 >= 阈值
                             │
                             ▼
                    ┌─────────────────┐
                    │      OPEN       │
                    │   (熔断状态)     │
                    └────────┬────────┘
                             │
                             │ 超时后
                             │
                             ▼
                    ┌─────────────────┐
                    │   HALF_OPEN     │
                    │   (半开状态)     │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              │              ▼
         成功请求            │         失败请求
              │              │              │
              ▼              │              ▼
        ┌─────────┐          │        ┌─────────┐
        │ CLOSED  │          │        │  OPEN   │
        └─────────┘          │        └─────────┘
                             │
```

#### 4.2.3 接口设计

```typescript
interface CircuitBreakerConfig {
  failureThreshold: number;      // 连续失败次数阈值（默认 5）
  successThreshold: number;      // 半开状态成功次数阈值（默认 2）
  openDuration: number;          // 熔断持续时间 ms（默认 30000）
  halfOpenMaxCalls: number;      // 半开状态最大调用次数（默认 3）
}

type CircuitState = 'CLOSED' | 'OPEN' | 'HALF_OPEN';

interface CircuitBreakerStats {
  state: CircuitState;
  failureCount: number;
  successCount: number;
  lastFailureAt?: Date;
  lastSuccessAt?: Date;
  nextRetryAt?: Date;
}
```

#### 4.2.4 实现伪代码

```typescript
class CircuitBreaker {
  private state: CircuitState = 'CLOSED';
  private failureCount = 0;
  private successCount = 0;
  private lastFailureAt?: Date;
  private openSince?: Date;

  constructor(private config: CircuitBreakerConfig) {}

  async execute<T>(fn: () => Promise<T>): Promise<T> {
    // 检查是否可以从 OPEN 转为 HALF_OPEN
    if (this.state === 'OPEN') {
      if (this.shouldTransitionToHalfOpen()) {
        this.transitionTo('HALF_OPEN');
      } else {
        throw new Error('Circuit breaker is OPEN');
      }
    }

    try {
      const result = await fn();
      this.recordSuccess();
      return result;
    } catch (error) {
      this.recordFailure();
      throw error;
    }
  }

  private recordSuccess(): void {
    this.successCount++;
    this.failureCount = 0;
    this.lastSuccessAt = new Date();

    if (this.state === 'HALF_OPEN' && this.successCount >= this.config.successThreshold) {
      this.transitionTo('CLOSED');
    }
  }

  private recordFailure(): void {
    this.failureCount++;
    this.successCount = 0;
    this.lastFailureAt = new Date();

    if (this.state === 'HALF_OPEN') {
      this.transitionTo('OPEN');
    } else if (this.failureCount >= this.config.failureThreshold) {
      this.transitionTo('OPEN');
    }
  }

  private shouldTransitionToHalfOpen(): boolean {
    if (!this.openSince) return false;
    return Date.now() - this.openSince.getTime() >= this.config.openDuration;
  }

  private transitionTo(state: CircuitState): void {
    this.state = state;
    if (state === 'OPEN') {
      this.openSince = new Date();
    } else if (state === 'CLOSED') {
      this.failureCount = 0;
      this.successCount = 0;
      this.openSince = undefined;
    } else if (state === 'HALF_OPEN') {
      this.successCount = 0;
    }
  }

  getStats(): CircuitBreakerStats {
    return {
      state: this.state,
      failureCount: this.failureCount,
      successCount: this.successCount,
      lastFailureAt: this.lastFailureAt,
      lastSuccessAt: this.lastSuccessAt,
      nextRetryAt: this.state === 'OPEN' && this.openSince
        ? new Date(this.openSince.getTime() + this.config.openDuration)
        : undefined,
    };
  }
}
```

### 4.3 过期缓存降级

#### 4.3.1 设计说明

当所有数据源都失败时，使用过期的缓存数据作为降级方案。

#### 4.3.2 流程图

```
┌───────────────────────────────────────────────────────────────────┐
│                        FetchProductUseCase                         │
│                                                                    │
│  1. 检查新鲜缓存                                                   │
│     ├─ 命中 → 返回 (degradationLevel: FRESH_CACHE)                │
│     └─ 未命中 ↓                                                   │
│                                                                    │
│  2. 检查数据库                                                     │
│     ├─ 命中 → 返回 (degradationLevel: DATABASE)                   │
│     └─ 未命中 ↓                                                   │
│                                                                    │
│  3. 检查过期缓存 (保存用于降级)                                     │
│     ├─ 存在 → 保存 staleFallback                                  │
│     └─ 不存在 → staleFallback = null                              │
│                                                                    │
│  4. 尝试数据源 (含故障转移)                                         │
│     ├─ 成功 → 返回 (degradationLevel: PRIMARY/FALLBACK_SOURCE)    │
│     └─ 全部失败 ↓                                                 │
│                                                                    │
│  5. 使用过期缓存降级                                               │
│     ├─ staleFallback 存在 → 返回 (degradationLevel: STALE_CACHE)  │
│     │   + 标记 isDegraded: true                                   │
│     └─ 不存在 ↓                                                   │
│                                                                    │
│  6. 返回错误 (degradationLevel: ERROR)                            │
│     + 发送告警                                                    │
└───────────────────────────────────────────────────────────────────┘
```

#### 4.3.3 接口设计

```typescript
interface FetchProductResult {
  product: ProductData | null;
  cached: boolean;
  source: string;
  latencyMs: number;
  degradationLevel: DegradationLevel;
  isDegraded: boolean;           // 是否处于降级模式
  staleCacheAge?: number;        // 过期缓存年龄（毫秒）
}

interface CacheProvider {
  // 扩展接口
  getWithFallback<T>(key: string): Promise<{
    data: T;
    isStale: boolean;
    age: number;      // 缓存年龄（毫秒）
  } | null>;
}
```

#### 4.3.4 实现伪代码

```typescript
async execute(
  platform: Platform, 
  platformId: string, 
  useCache = true
): Promise<FetchProductResult> {
  const start = Date.now();
  let staleFallback: { data: ProductData; age: number } | null = null;

  // Layer 1: 检查新鲜缓存
  if (useCache) {
    const cached = await this.cacheProvider.getProduct(platform, platformId);
    
    if (cached) {
      // 保存过期缓存用于降级
      if (cached.isStale) {
        staleFallback = {
          data: cached.data as ProductData,
          age: this.calculateCacheAge(cached),
        };
      } else {
        return {
          product: cached.data as ProductData,
          cached: true,
          source: "cache",
          latencyMs: Date.now() - start,
          degradationLevel: DegradationLevel.FRESH_CACHE,
          isDegraded: false,
        };
      }
    }
  }

  // Layer 2: 检查数据库
  const existing = await this.repository.findByPlatformId(platform, platformId);
  if (existing) {
    return {
      product: existing.toData(),
      cached: true,
      source: "database",
      latencyMs: Date.now() - start,
      degradationLevel: DegradationLevel.DATABASE,
      isDegraded: false,
    };
  }

  // Layer 3: 尝试数据源（含故障转移）
  try {
    const result = await this.gateway.fetchProduct(platformId, { 
      useCache,
      onSourceFailure: (sourceId, error) => {
        this.alertService.sendFetchErrorAlert(platform, platformId, error.message);
      },
    });

    if (result.success && result.data) {
      return {
        product: result.data,
        cached: false,
        source: result.source,
        latencyMs: Date.now() - start,
        degradationLevel: result.attempts?.length === 1
          ? DegradationLevel.PRIMARY_SOURCE
          : DegradationLevel.FALLBACK_SOURCE,
        isDegraded: false,
      };
    }
  } catch (error) {
    // 所有数据源失败，继续尝试降级
    this.logger.warn("All data sources failed", { platform, platformId, error });
  }

  // Layer 4: 使用过期缓存降级
  if (staleFallback) {
    this.logger.warn("Using stale cache as fallback", { 
      platform, 
      platformId, 
      staleAgeMs: staleFallback.age 
    });
    
    return {
      product: staleFallback.data,
      cached: true,
      source: "cache-stale",
      latencyMs: Date.now() - start,
      degradationLevel: DegradationLevel.STALE_CACHE,
      isDegraded: true,
      staleCacheAge: staleFallback.age,
    };
  }

  // Layer 5: 返回错误
  this.alertService.sendFetchErrorAlert(platform, platformId, "No data available");

  return {
    product: null,
    cached: false,
    source: "error",
    latencyMs: Date.now() - start,
    degradationLevel: DegradationLevel.ERROR,
    isDegraded: true,
  };
}
```

#### 4.4.3 接口设计

```typescript
interface SourceHealthTracker {
  // 记录成功
  recordSuccess(sourceId: string): void;
```

### 4.5 成本感知选择

#### 4.5.1 设计说明

在数据源选择时考虑调用成本，在保证可用性的前提下优化成本。

#### 4.5.2 选择策略

```typescript
interface SourceSelectionStrategy {
  // 纯优先级策略（默认）
  priorityFirst(sources: DataSource[]): DataSource[];
  
  // 成本优先策略
  costFirst(sources: DataSource[]): DataSource[];
  
  // 混合策略：优先级为主，同优先级按成本排序
  hybrid(sources: DataSource[]): DataSource[];
  
  // 智能策略：考虑成功率、延迟、成本
  smart(sources: DataSource[], health: Map<string, SourceHealth>): DataSource[];
}
```

#### 4.5.3 智能选择算法

```typescript
function smartSelection(
  sources: DataSource[],
  health: Map<string, SourceHealth>,
  options: { preferLowCost?: boolean }
): DataSource[] {
  return sources
    .filter(s => {
      const h = health.get(s.id);
      return s.isAvailable && 
             s.hasRemainingQuota() &&
             (!h || h.status !== 'UNHEALTHY');
    })
    .sort((a, b) => {
      const healthA = health.get(a.id);
      const healthB = health.get(b.id);
      
      // 1. 优先级（数值小的优先）
      if (a.priority !== b.priority) {
        return a.priority - b.priority;
      }
      
      // 2. 成功率（高的优先）
      const successRateA = healthA?.successRate ?? 1;
      const successRateB = healthB?.successRate ?? 1;
      if (Math.abs(successRateA - successRateB) > 0.1) {
        return successRateB - successRateA;
      }
      
      // 3. 成本（低的优先）
      return a.costPerCall - b.costPerCall;
    });
}
```
