# 数据采集模块架构

## 1. 概述

本文档描述美潮电商数据采集模块的整体架构设计，包括模块划分、层次结构、依赖关系和扩展机制。

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| **六边形架构** | 领域核心无外部依赖，通过端口与外部交互 |
| **依赖倒置** | 高层模块不依赖低层模块，都依赖抽象 |
| **单一职责** | 每个模块只负责一个功能领域 |
| **开闭原则** | 对扩展开放，对修改关闭 |
| **接口隔离** | 接口最小化，不强迫实现不需要的方法 |

## 4. 模块划分

### 4.1 领域层 (M1)

**职责**: 定义业务概念、规则和抽象接口

```
src/domain/
├── types.ts                 # 类型定义
├── entities/
│   └── Product.ts          # 商品实体
├── value-objects/
│   ├── DataSource.ts       # 数据源值对象
│   └── Quota.ts            # 配额值对象
└── ports/
    ├── ProductRepository.ts # 存储端口
    ├── PlatformGateway.ts   # 平台网关端口
    └── CacheProvider.ts     # 缓存端口
```

**设计规则**:
- 无外部依赖
- 纯 TypeScript 类型和方法
- 不依赖框架或库

### 4.2 基础设施层 (M2-M4)

**职责**: 实现领域层定义的端口接口

```
src/infrastructure/
├── storage/
│   ├── postgres.ts         # PostgreSQL 连接
│   └── ProductRepository.ts # Repository 实现
├── cache/
│   ├── redis.ts            # Redis 连接
│   └── CacheProvider.ts    # CacheProvider 实现
├── adapters/
│   ├── BasePlatformAdapter.ts  # 抽象基类
│   ├── TaobaoAdapter.ts        # 淘宝适配器
│   ├── AmazonAdapter.ts        # Amazon 适配器
│   └── MockPlatformGateway.ts  # 测试用 Mock
└── registry/
    └── PlatformRegistry.ts # 平台注册中心
```

**设计规则**:
- 依赖领域层的端口接口
- 实现具体的数据库、缓存、API 调用
- 可替换实现（测试时用 Mock）

### 4.3 应用层 (M5-M6)

**职责**: 编排业务用例，协调各模块

```
src/application/
├── pipeline/
│   ├── types.ts            # 管道类型
│   ├── DataPipeline.ts     # 管道编排器
│   └── filters/
│       ├── FetchFilter.ts
│       ├── ValidateFilter.ts
│       ├── DedupeFilter.ts
│       ├── StoreFilter.ts
│       └── CacheFilter.ts
├── use-cases/
│   ├── FetchProductUseCase.ts
│   └── SearchProductsUseCase.ts
└── services/
    ├── QuotaService.ts
    └── AlertService.ts
```

**设计规则**:
- 依赖领域层的端口接口
- 不依赖具体实现
- 通过依赖注入获取实现

### 4.4 接口层 (M7)

**职责**: 暴露外部访问入口

```
extensions/meichao-ecom/
├── index.ts                 # 插件入口
└── package.json
```

**设计规则**:
- 组装和初始化各层
- 提供统一入口

## 7. 扩展机制

### 7.1 添加新平台

1. 实现 `PlatformGateway` 接口
2. 继承 `BasePlatformAdapter`
3. 注册到 `PlatformRegistry`

```typescript
// 1. 创建适配器
class NewPlatformAdapter extends BasePlatformAdapter {
  getPlatform() { return "newplatform"; }
  
  async fetchProduct(platformId, options) {
    // 实现获取逻辑
  }
}

// 2. 注册
PlatformRegistry.register(NewPlatformAdapter.create());
```

### 7.2 添加新过滤器

1. 实现 `PipelineFilter` 接口
2. 添加到管道

```typescript
class CustomFilter implements PipelineFilter {
  name = "custom";
  
  async execute(context, input) {
    // 处理逻辑
    return { products, errors, stats };
  }
}

pipeline.addFilter(new CustomFilter());
```

### 7.3 添加新数据源

1. 配置数据源
2. 添加到适配器

```typescript
adapter.addDataSource(DataSource.create({
  id: "new_source",
  platform: "taobao",
  type: "third_party_api",
  priority: 4,
  costPerCall: 0.02,
  dailyQuota: 2000,
  usedQuota: 0,
  isAvailable: true,
}));
```

## 9. 错误处理

### 9.1 错误类型

| 错误码 | 说明 | 处理方式 |
|--------|------|----------|
| `GATEWAY_NOT_FOUND` | 平台网关未注册 | 返回错误 |
| `FETCH_FAILED` | 数据获取失败 | 尝试降级 |
| `VALIDATION_FAILED` | 数据验证失败 | 记录错误 |
| `DUPLICATE` | 重复数据 | 跳过 |
| `STORE_ERROR` | 存储错误 | 记录错误 |
| `CACHE_ERROR` | 缓存错误 | 忽略继续 |

### 9.2 错误传播

```
Filter → FilterResult.errors[] → Pipeline → PipelineResult.errors[]
```

### 12.2 核心组件

| 组件 | 职责 | 位置 |
|------|------|------|
| **CircuitBreaker** | 熔断器，防止级联故障 | `infrastructure/circuit-breaker/` |
| **CooldownManager** | 冷却管理，指数退避 | `infrastructure/cooldown/` |
| **HealthProbeScheduler** | 健康探测调度 | `infrastructure/health/` |
| **DecisionLogger** | 决策日志记录 | `infrastructure/logging/` |
| **ErrorClassifier** | 错误分类 | `infrastructure/classification/` |

### 12.3 六层降级流程

```
Layer 1: Fresh Cache (Redis TTL)
    ↓ miss
Layer 2: Database (新鲜度检查)
    ↓ stale/not found
Layer 3: Primary Source (熔断器 + 冷却检查)
    ↓ blocked
Layer 4: Fallback Sources (依次尝试)
    ↓ all failed
Layer 5: Stale Cache (过期缓存)
    ↓ miss
Layer 6: Error
```

### 12.4 错误分类

| 错误类型 | 说明 | 严重程度 |
|----------|------|----------|
| `auth` | 认证失败 | 普通 |
| `auth_permanent` | 认证永久失效 | 严重 |
| `rate_limit` | 速率限制 | 普通 |
| `overloaded` | 服务过载 | 普通 |
| `billing` | 计费问题 | 严重 |

### 12.5 配置项

```typescript
interface DegradationConfig {
  circuitBreaker: {
    enabled: boolean;           // 是否启用熔断器
    failureThreshold: number;   // 失败阈值 (默认: 5)
    openDuration: number;       // 熔断持续时间 (默认: 30000ms)
    halfOpenMaxCalls: number;   // 半开状态最大调用次数 (默认: 1)
    successThreshold: number;   // 恢复成功阈值 (默认: 3)
  };
  cooldown: {
    baseMinutes: number;        // 基础冷却时间 (默认: 5分钟)
    maxMinutes: number;         // 最大冷却时间 (默认: 60分钟)
    severeMultiplier: number;   // 严重错误倍数 (默认: 12)
    probeWindowMinutes: number; // Probe窗口 (默认: 2分钟)
    probeMinIntervalSeconds: number; // Probe最小间隔 (默认: 30秒)
  };
  healthProbe: {
    interval: number;           // 探测间隔 (默认: 60000ms)
    timeout: number;            // 探测超时 (默认: 10000ms)
    unhealthyThreshold: number; // 不健康阈值 (默认: 3)
    recoveryThreshold: number;  // 恢复阈值 (默认: 2)
  };
}
```
