我来梳理一下整个问题的来龙去脉和我们的修复步骤：

## 问题根源

尽管你已经通过 nvm 安装了 Node.js v24.8.0，但在非登录 shell 环境中，系统的 Node.js v18 会**优先**出现在 PATH 中：

- 系统 Node：`/usr/bin/node` v18.19.1
- Nvm Node：`~/.nvm/versions/node/v24.8.0/bin/node` v24.8.0

当你最初运行 `npm link` 时，环境没有加载 nvm，所以虽然它创建了 `openclaw` 的符号链接，但 shell 仍然会找到错误版本的 Node。

## 完整修复流程：

1. **确认问题：** 一开始找不到 `openclaw` 命令。我们在 `/projects/openclaw` 找到了源代码，并在 package.json 中看到了二进制入口。

2. **重新执行 `npm link`：** 在加载 nvm 之后重新链接，把它放到正确的路径：
```bash
source ~/.nvm/nvm.sh && cd /projects/openclaw && npm unlink openclaw && npm link
```
这就在 nvm 的 bin 目录创建了符号链接：`/home/dusx/.nvm/versions/node/v24.8.0/bin/openclaw`

3. **验证修复：** 重新链接后，`openclaw --version` 现在正确输出版本：
```
OpenClaw 2026.3.26 (2904722)
```

4. **运行健康检查：** `openclaw doctor --non-interactive` 成功完成，只有一个预期错误（meichao-ecom 扩展缺少 puppeteer）。

## 为什么现在你的 shell 显示 v24.8.0：
当你打开一个新终端运行 `node -v` 时，现在会得到 v24.8.0，原因是：
- 现在你的 shell 配置文件加载了 nvm，nvm 的 bin 目录 (`/home/dusx/.nvm/versions/node/v24.8.0/bin`) 在 PATH 中排列在 `/usr/bin` **之前**。

## 唯一剩下的问题：
meichao-ecom 扩展因为缺少 puppeteer 无法加载。如果你想修复它，运行：
```bash
cd /projects/openclaw/extensions/meichao-ecom && npm install
```
这会安装包括 puppeteer 在内的缺失依赖。

搞定！现在 `openclaw` 命令已经完全在正确的 Node.js 版本下正常工作了。
